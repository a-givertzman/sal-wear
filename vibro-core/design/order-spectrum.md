## Спектральный анализ диапазона 1X, 2X, 3X

Мониторинг низкочастотных дефектов вроде дисбаланса (1X), несоосности (2X) и проблем опор/ослабления креплений (3X).

## 1. Количество точек на оборот ($N_{rev} = 64$)

* Теория: Для наблюдения 3X порядка с запасом Найквиста-Шеннона $2.56$ вам действительно нужно минимум $3 \times 2.56 = 7.68 \rightarrow 8$ точек на оборот.
* Практика: Выбор $N_{rev} = 64$ — это отличный выбор. Максимальный наблюдаемый порядок будет равен $64 / 2 = 32$. Для низкочастотной диагностики этого более чем достаточно (перекрывает даже высшие гармоники муфт и ремней). Но главное — цифровой антиалиасинговый фильтр нижних частот при $N_{rev}=64$ реализовать гораздо проще, у него будет пологий и стабильный спад.

## 2. Разрешение по частоте ($\Delta O = 0.1$) — Критическая зона риска!

Для подшипников разрешение $0.1$ порядка было отличным. Но для низких порядков (1X, 2X, 3X) разрешение $0.1$ порядка — это слишком грубо.

* Почему это опасно: Самый частый ложный диагноз в вибродиагностике — это путаница между дисбалансом ротора (строго 1.0X) и электрической наводкой/фоном питающей сети (50 Гц / 60 Гц).
* Пример: Если ваш двигатель вращается на частоте 2940 об/мин (49 Гц), то сетевая наводка 50 Гц будет находиться на порядке $50 / 49 = 1.0204X$.
* При разрешении спектра $\Delta O = 0.1$ пик дисбаланса ($1.0X$) и пик сети ($1.02X$) сольются в один жирный пик. Вы не сможете понять, бьет ли у вас ротор физически или это проблема в статоре/электрике.
* Инженерный стандарт: Для низких порядков (1X..3X) стандартным является разрешение не хуже $0.02 \dots 0.01$ порядка (накопление 50–100 оборотов вала).

## 3. Пересчет буфера под целевые задачи
Если мы целимся в надежное разделение механических и электрических проблем:

* Целевое разрешение: $\Delta O = 0.015$ порядка (накопление $\approx 64$ оборотов).
* Расчет: $N_{fft} = N_{rev} \times K = 64 \times 64 = 4096$ точек.
* Если ресурсы жестко ограничены и вы оставляете текущие константы ($N_{rev} = 64, N_{fft} = 1024$), то ваше реальное разрешение будет $64 / 1024 = 0.0625$ порядка (накопление 16 оборотов). Это приемлемо для грубого трендинга, но недостаточно для точной аналитики.

## Часть 2: Исправление критических багов в коде Rust
В коде типажа Eval содержатся логические ошибки, которые приведут к падению программы или порче данных:

   1. Инвертированное условие проверки размера: ctx.order_samples.len() <= ctx.fft_buff.capacity(). Из-за знака <= код будет падать с ошибкой всегда, когда размер новой пачки данных нормальный (меньше буфера).
   2. Выполнение FFT на пустом буфере: Код вызывает self.fft.process(&mut ctx.fft_window) на каждом шаге конвейера, независимо от того, выполнилось ли условие if ctx.fft_buff.is_full(). Обработка должна происходить строго внутри блока условия.
   3. Отсутствие оконной функции (Leakage): Для низких порядков спектральное растекание (spectral leakage) критично. Без наложения окна (например, Ханнинга) боковые лепестки от пика 1X размоются и закроют собой соседние частоты.

Вот полностью исправленный и математически выверенный код:

use std::sync::Arc;use rustfft::{Fft, FftPlanner};use num_complex::Complex;
// Константы оптимизированы для низкочастотной диагностики (1X, 2X, 3X)const POINTS_PER_TURN: usize = 64;   // Nrev: Оптимально для фильтрации низких порядковconst TARGET_RESOLUTION: f64 = 0.016; // Требуемое разрешение для разделения 1X и сети (~64 оборота)
pub struct OrderSpectrum<Child> {
    sample_rate: f64,
    child: Child,
    fft: Arc<dyn Fft<f32>>,
    dbg: Dbg,
    window_coefficients: Vec<f32>, // Предрассчитанные веса окна Ханнинга
}
impl<Child> OrderSpectrum<Child>where
    Child: Eval<ImbContext, ImbContext> + Send + 'static 
{
    pub fn new(parent: &Dbg, sample_rate_hz: impl Into<f64>, child: Child) -> Self {
        let dbg = Dbg::new(parent, me::<Self>());
        let fft_size = Self::fft_buffer_size();
        log::debug!("{dbg}.new | Низкочастотный OrderSpectrum. Размер окна FFT: {fft_size}");
        
        let mut planner = FftPlanner::new();
        let fft = planner.plan_fft_forward(fft_size);
        
        // Генерация окна Ханнинга для подавления спектрального растекания на 1X..3X
        let window_coefficients = (0..fft_size)
            .map(|i| 0.5 * (1.0 - (2.0 * std::f32::consts::PI * i as f32 / (fft_size - 1) as f32).cos()))
            .collect();

        Self {
            sample_rate: sample_rate_hz.into(),
            child,
            fft,
            dbg,
            window_coefficients,
        }
    }

    /// Расчет размера буфера. 64 / 0.016 = 4000 отсчетов -> Ближайшая степень двойки = 4096.
    /// Это дает реальное накопление 64 оборотов вала и разрешение 0.0156 порядка.
    pub fn fft_buffer_size() -> usize {
        let min_needed_samples = POINTS_PER_TURN as f64 / TARGET_RESOLUTION;
        (min_needed_samples.round() as usize).next_power_of_two()
    }
}
impl<Child> Eval<ImbContext, ImbContext> for OrderSpectrum<Child>where
    Child: Eval<ImbContext, ImbContext> + Send + 'static 
{
    #[inline]
    fn eval(&self, ctx: ImbContext) -> ImbContext {
        // 1. Получаем угловые сэмплы из предыдущего шага ресемплера
        let mut ctx = self.child.eval(ctx);
        if ctx.err.is_some() {
            return ctx.pass_err(&self.dbg, "eval");
        }

        // Проверка: поместятся ли новые данные в свободное место кольцевого буфера
        if ctx.order_samples.len() > ctx.fft_buff.free_space() {
            ctx.err = Some(Error::new(&self.dbg, "eval")
                .err(format!("Переполнение FIFO: новые угловые сэмплы ({}) не помещаются", ctx.order_samples.len())));
            return ctx;
        }

        // 2. Накапливаем данные в FIFO
        ctx.fft_buff.push_chunk(&ctx.order_samples[..]);

        // 3. Вычисляем спектр ТОЛЬКО при полном заполнении окна
        if ctx.fft_buff.is_full() {
            let real_samples = ctx.fft_buff.read_window(); 
            
            // Перенос в комплексный массив с ОДНОВРЕМЕННЫМ наложением оконной функции
            // Это критично для точного определения амплитуды дисбаланса (1X)
            for (i, &sample) in real_samples.iter().enumerate() {
                let windowed_sample = sample * self.window_coefficients[i];
                ctx.fft_window[i] = Complex::new(windowed_sample, 0.0);
            }

            // Выполнение In-place FFT (Прямое преобразование)
            self.fft.process(&mut ctx.fft_window);
            
            // Результат: первые (Nfft / 2) элементов — это порядки от 0 до 32X с шагом 0.0156X.
            // Пик дисбаланса будет строго в бине (1.0 / 0.0156) = 64-й элемент массива.
        }

        ctx
    }

    fn exit(&self) {
        self.child.exit();
    }
}

## Часть 3: Инженерная документация по низкочастотной вибродиагностике
Для защиты этого алгоритмического решения и его калибровки вам понадобятся следующие отраслевые нормативные документы и методические указания:
## 1. Профильные стандарты ISO (Оценка состояния машин по 1X, 2X, 3X)

* ISO 20816-1:2016 (Mechanical vibration — Measurement and evaluation of machine vibration) — Основной глобальный стандарт, заменивший старые ISO 10816 и ISO 7919. Содержит жесткие таблицы допустимых значений среднеквадратичного значения (СКЗ/RMS) виброскорости и виброперемещения для роторных машин разной мощности. По нему вы будете настраивать пороги предупреждения (Warning/Alarm) для тренда 1X порядка.
* ISO 1940-1 (Vibrations - Balance quality requirements for rotors in a constant state) — Инженерная база по дисбалансам. Задает классы точности балансировки ($G 1.0, G 2.5, G 6.3$). Помогает рассчитать, какая амплитуда 1X порядка допустима для конкретного типа вашего ротора.

## 2. Диагностическая матрица для вашего спектра (Что искать в коде)
Когда ваше FFT выдаст массив амплитуд, логика автоматического поиска дефектов в системе CMS должна опираться на следующие правила:

* Дисбаланс (Unbalance): Резкий рост амплитуды строго на 1.0X порядке. В радиальном направлении (горизонталь/вертикаль).
* Несоосность валов/муфты (Misalignment): Доминирование пика на 2.0X порядке, часто сопровождается повышенной осевой (аксиальной) вибрацией на 1.0X и 2.0X.
* Механическое ослабление (Mechanical Looseness): Появление сильного пика на 3.0X порядке, а также возникновение дробных гармоник (0.5X, 1.5X, 2.5X) и целой цепочки высших порядков (4X..10X), вызванных нелинейностью зазоров в опорах.

## 3. Рекомендуемая инженерная литература

* Методические указания: "Диагностика роторного оборудования по цепям спектра вибрации" (Барков А.В., Баркова Н.А., учебные пособия СЗУЦ ВИБРОТЕХНИК). Это лучшая русскоязычная инженерная школа по практической вибродиагностике. Там подробно расписано, почему разрешение спектра в зоне низких частот должно быть максимальным.
* Книга: "Machinery Malfunction Diagnosis and Correction" (Автор: Charles Jackson). Практическое руководство по решению проблем с дисбалансом и соосностью на промышленных объектах.

2. Как глубоко в порядки целесообразно заглядывать?
Для диагностики подшипников качения стандартной и общепринятой в вибродиагностике практикой является анализ спектра до 50-го порядка (в редких случаях — до 100-го).
Вот почему глубокий анализ имеет смысл и где находится разумный предел:
Зона 1: Базовые дефекты (1–10 порядки)
Здесь зарождаются фундаментальные частоты дефектов подшипника (вы их посчитаете по геометрии). Например:

	•	Сепаратор (FTF) — обычно около 0.4 порядка.
	•	Тела качения (BSF) — обычно 2.0–3.0 порядка.
	•	Наружное кольцо (BPFO) — обычно 3.0–8.0 порядка.
	•	Внутреннее кольцо (BPFI) — обычно 5.0–12.0 порядка.
Зона 2: Развитые дефекты и гармоники (10–30 порядки) — Самая целесообразная зона
Когда на подшипнике появляется реальный скол или раковина, датчик фиксирует не просто плавную синусоиду, а резкие удары каждый раз, когда шарик перекатывается через дефект.

	•	В спектре эти удары порождают длинный хвост гармоник (2-я, 3-я, 4-я и т.д. кратности от базовой частоты дефекта).
	•	Пример: Если дефект наружного кольца равен 5.2 порядка, то вы увидите пики на 10.4, 15.6, 20.8, 26.0 порядках.
	•	Целесообразность: Видеть этот хвост гармоник критически важно. Один одинокий пик на 5.2 порядка может быть случайным шумом, но если вы видите его стройный ряд гармоник до 25–30 порядка — это 100% подтвержденный дефект.
Зона 3: Сильный износ и «боковые полосы» (30–50 порядки)
Когда подшипник близок к разрушению, люфты увеличиваются. Частоты дефектов начинают модулироваться частотой вращения самого вала (1-м порядком). Вокруг высших гармоник появляются «расчески» (боковые полосы) с шагом в ±1 порядок. Чтобы их не потерять, спектр смотрят до 50-го порядка.
Зона 4: Выше 50–60 порядка — Обычно нецелесообразно
Заглядывать выше 60–80 порядка в спектре углового домена обычно нет смысла по двум причинам:

	1.	Энергия ударов там затухает, и сигналы тонут в шумах.
	2.	Высокочастотный звон металла (резонансы самого корпуса подшипника) в этой зоне лучше анализировать другими методами (например, методом огибающей высокочастотной вибрации), а не прямым FFT.
Резюме для вашей настройки:
Ваша комбинация $N_{rev} = 256$ и $N_{fft} = 4096$ идеальна. Она позволит вам уверенно и с огромным запасом по качеству смотреть спектр до 50-го порядка, детально видя все зарождающиеся дефекты, их гармоники и боковые полосы модуляции.
